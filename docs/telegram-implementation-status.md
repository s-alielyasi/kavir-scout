# وضعیت پیاده‌سازی تلگرام — ۲۰۲۶-۱۰-۲۹

این سند وضعیت فعلی را ثبت می‌کند. [راهنمای اجرا](telegram-operations.md)،
[معماری](architecture.md) و [فهرست مستندات](README.md) مرجع کار روزمره‌اند.
[پلن اولیه](telegram-integration-plan.md) سابقهٔ طراحی بر مبنای commit
`3e078d3` است؛ محدودیت «فقط مستندات» و هدف چهارحلقه‌ای آن مربوط به تسک اولیه‌اند.

## تنظیم و وضعیت تأییدشده

- محصول `Perfect (R14) KB27`، سایز `185/65R14` و تعداد **۲ حلقه** توسط مالک
  تأیید شده‌اند؛ پیش‌فرض کد و هر دو فایل نمونه با این مقدار یکسان‌اند.
- محیط مستقل Python 3.12.16 و وابستگی‌های مقید در Linux آماده‌اند. مرورگر
  Google Chrome نصب‌شده با `BROWSER_CHANNEL=chrome` استفاده می‌شود؛ نصب
  Chromium همراه نسخهٔ فعلی Playwright روی Ubuntu 20.04 پشتیبانی نمی‌شود.
- مالک توکن و شناسه‌ها را در `.env` خصوصی تنظیم کرده است. اتصال واقعی تلگرام
  از پراکسی موجود دستگاه برقرار شد؛ `TELEGRAM_PROXY_URL` فقط دو کلاینت تلگرام
  را تنظیم می‌کند و مسیر مرورگر فروشگاه را تغییر نمی‌دهد.
- پاسخ‌های واقعی `/start` و `/status` و امکان کپی آن‌ها توسط مالک تأیید شدند.
  خروجی عمومی قابل کپی است؛ prompt کد ملی/OTP و پیام پرداخت حفاظت محتوا دارند.
- `DRY_RUN=true` و `LIVE_CHECKOUT_APPROVED=false` برقرارند. روشن‌شدن، restart و
  `/start` اجرا را فعال نمی‌کنند؛ هر روز به `/arm` تازه نیاز است.
- برای تست صریح ورود تا یک بررسی موجودی، `/test_inventory` یا فلگ
  `--test-inventory` اضافه شد؛ فقط در حالت مشاهده، مستقل از ساعت و با مهلت
  کل ده دقیقه اجرا می‌شود و برای هر نتیجه پیش از انتخاب/سفارش پایان می‌یابد.

- اتصال مستقیم مرورگر با `BROWSER_DIRECT_CONNECTION=true` اضافه شد؛ صفحهٔ عمومی
  فروشگاه در مرورگر نمایان پاسخ ۲۰۰ داد و هم‌زمان API تلگرام از پراکسی محلی
  قابل دسترس بود. تلگرام موبایل می‌تواند ورودی‌ها را بدهد؛ کلاینت دسکتاپ لازم نیست.

| فاز پلن | وضعیت |
|---|---|
| ۱–۲ | تنظیمات معتبر بدون هویت، زمان‌بندی تهران، مدل وضعیت، broker و درگاه تعامل مستقل |
| ۳–۵ | چرخهٔ صریح PTB، gate مشترک و بررسی user/chat، handler کوتاه، dedup و پاسخ مقید به prompt |
| ۶–۷ | کد ملی و OTP در زمان اجرا، تأیید دستی حساب نشست موجود، انتظار نتیجهٔ واقعی DOM و پاک‌سازی مراجع مصرف‌شده |
| ۸–۹ | انتظار قبل از ۸، بازه‌های ۵/۱۵/۳۰ ثانیه، یادآوری یک‌باره، عدم هم‌پوشانی و قطع نتیجهٔ دیررس |
| ۱۰–۱۱ | dry-run پیش از انتخاب، barrier ماندگار تلاش سفارش، بازخوانی محصول/تعداد و منشأ معتبر درگاه |
| ۱۲–۱۳ | دکمهٔ خصوصی پرداخت بدون فایل/لاگ URL، retry فقط تحویل، cancel پاسخ‌گو، resume مقید و پاک‌سازی محدود |
| ۱۴ | تست و بازبینی محلی انجام شده؛ ممیزی واقعی ذخیره‌سازی مرورگر هنوز باقی است |
| ۱۵–۱۶ | تنظیم دستگاه و تست پیام‌های واقعی تلگرام انجام شده؛ اعتبارسنجی واقعی فروشگاه و سفارش تکمیل نشده |

**۱۰۳ تست دائمی** با دستور قابل اجرای خود مخزن و Chrome نصب‌شده موفق شدند.
fixtureهای مشترک در `tests/browser_support.py` هستند و درخواست‌های بدون route
ساختگی را مسدود می‌کنند. ردیف‌های چهارحلقه‌ای، دادهٔ مستقل تست محدودیت‌اند.
جزئیات نسخه، روش و محدودیت هر اجرا در [verification.md](verification.md) آمده است.

## حفاظت‌های بررسی‌شده

- آیکن و عنوان مترادف ثبت، مسیر ارسال سفارش را دوباره فعال نمی‌کند.
- دکمهٔ امن دیگر، بررسی تعدادِ دکمهٔ خرید را حذف نمی‌کند.
- کارت مبهم، ردیف ترکیبی، کالای اضافه و تعداد منفی رد می‌شوند.
- درگاه قبلی یا تب نامرتبط به‌عنوان نتیجهٔ checkout جاری پذیرفته نمی‌شود.
- تغییر metadata به‌تنهایی پایان refresh نیست؛ دکمهٔ disabled با reload دور زده نمی‌شود.
- OTP مصرف‌شده در redactor باقی نمی‌ماند. export کل origin storage حذف شده؛
  پشتیبان اختیاری CLI فقط کوکی فروشگاه همان پروفایل است و در bot خاموش است.
- marker حل‌نشده بعد از crash، cancel یا تغییر روز، خرید تازه را مسدود نگه می‌دارد؛
  CLI نیز همین کنترل را رعایت می‌کند.

## بررسی‌های باقی‌مانده

۱. ورود واقعی از تلگرام پیش از ساعت ۸، دریافت کد و تطبیق حساب روی همین دستگاه.
۲. یک اجرای واقعی بدون سفارش در بازهٔ صبح؛ موجودی، cooldown، توقف و پایان ۸:۱۵.
۳. ممیزی دادهٔ هویتی، OTP، cache و autofill در پروفایل واقعی مرورگر.
۴. تأیید شرایط جاری تعداد هدف و selectorهای واقعی checkout.
۵. سفارش کنترل‌شده و تحویل قابل استفادهٔ درگاه، فقط پس از درخواست صریح مرتبط.

تست fixture یا پاسخ تلگرام جای این بررسی‌ها را نمی‌گیرد. تأیید حساب خودکار،
قابل استفاده بودن لینک پرداخت روی تلفن، اجرای Windows و Python 3.11 واقعی هنوز
تأیید نشده‌اند. ممیزی آنلاین CVE نیز انجام نشده است.
