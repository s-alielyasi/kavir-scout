# وضعیت پیاده‌سازی تلگرام — ۲۰۲۶-۱۰-۲۹

مبنای طراحی: [پلن تلگرام](telegram-integration-plan.md)، commit اولیه `fd9c3ad`.
پیاده‌سازی محلی روی برنچ `feature/telegram-app` است. این سند جایگزین ادعای
«هیچ کد تلگرامی وجود ندارد» برای نسخهٔ فعلی است؛ اسناد verification قدیمی
سوابق تاریخی‌اند. [راهنمای اجرا و بازیابی](telegram-operations.md) رفتار فعلی را شرح می‌دهد.

## انجام‌شده در کد

| فاز پلن | وضعیت پیاده‌سازی محلی |
|---|---|
| ۱–۲ | BotSettings بدون هویت، تنظیمات معتبر، زمان‌بندی aware، مدل وضعیت، broker یک‌بارمصرف و درگاه تعامل مستقل از Telegram |
| ۳–۵ | lifecycle مستقل PTB، gate مشترک و بررسی مجدد user/chat، handlerهای کوتاه، dedup، reply correlation، حذف best-effort |
| ۶–۷ | حذف NATIONAL_ID از Config و ورودی ENV؛ ورودی runtime برای CLI و تلگرام؛ تأیید حساب نشست موجود، انتظار پاسخ واقعی، حذف مراجع OTP |
| ۸–۹ | بازه‌های ۵/۱۵/۳۰ ثانیه تهران، یادآوری یک‌باره، منع بازگشت روز/ساعت، قطع مهلت ورودی و نتیجهٔ دیررس، یک worker و رعایت cooldown |
| ۱۰–۱۱ | dry-run پیش از هر انتخاب، barrier ماندگارِ تلاش سفارش، بازخوانی محصول/تعداد و منشأ درگاه مرتبط با checkout جاری |
| ۱۲–۱۳ | دکمهٔ خصوصی درگاه بدون stdout/file، retry فقط ارسال با TTL، /cancel پاسخ‌گو، /resume مقید به checkpoint، پاک‌سازی محدود و قفل‌های OS |
| ۱۴ | تست‌های خودکار و بازبینی محلی انجام می‌شوند؛ ممیزی واقعی پروفایل/ذخیره‌سازی و شرایط دستگاه مقصد هنوز گیت انتشار است |
| ۱۵–۱۶ | اجرای زنده، تنظیم توکن واقعی، ورود واقعی، dry-run واقعی، سفارش واقعی و انتشار انجام نشده‌اند |

فازهای ۱۵ و ۱۶ با fixture تکمیل‌شده محسوب نمی‌شوند. DRY_RUN روشن و
LIVE_CHECKOUT_APPROVED خاموش پیش‌فرض‌اند؛ تغییر آن‌ها به تأیید گیت‌های راهنما
وابسته است. شروع سرویس، /start یا restart اجرای خرید را فعال نمی‌کند.

## اصلاحات بازبینی قبلی

نقص‌های بازتولیدشده به تست دائمی منتقل و در محدودهٔ محلی اصلاح شده‌اند:

- آیکن یا عنوان مترادف دکمه، فاز ثبت سفارش را دوباره فعال نمی‌کند.
- دکمه امن دیگرِ کارت نمی‌تواند preflight دکمهٔ خرید را حذف کند.
- ردیف‌های ترکیبی/کالای اضافه و کارت‌های تکراری با selectorهای متفاوت رد می‌شوند.
- درگاه از قبل بازشده یا تب نامرتبط نتیجه سفارش جاری نیست.
- پشتیبان کوکی به همان پروفایل مقید است؛ نشست موجود به تأیید دستی حساب نیاز دارد.
- تغییر metadata آغاز refresh، تأیید تکمیل موجودی نیست؛ دکمه disabled با reload دور زده نمی‌شود.
- تعداد منفی به مقدار مثبت تبدیل نمی‌شود.
- مسیر مستقیمِ هم‌تبِ درگاه بدون خواندن DOM بانک تحویل می‌شود؛ helperهای DOM نیز دامنه را کنترل می‌کنند.
- OTP تاریخی در redactor باقی نمی‌ماند و کل origin storage صادر نمی‌شود.

این اصلاحات، تغییرات احتمالی آیندهٔ DOM سایت یا وقوع همه خطاهای شبکه را پوشش
قطعی نمی‌دهند. selectorهای checkout واقعی همچنان مطابق سابقهٔ README تأیید زنده ندارند.

## دامنه و تحویل

- توکن یا شناسه واقعی درخواست/تنظیم نشده و هیچ پیام واقعی با ابزارها ارسال نشده است.
- `.env` و پروفایل خصوصی مالک بازنویسی نشده‌اند. تغییر قبلی TARGET_QUANTITY در
  `.env.example` حفظ می‌شود؛ حذف placeholder قدیمی NATIONAL_ID تغییر همین پیاده‌سازی است.
- نمونهٔ جداگانه `.env.telegram.example` چهار حلقه را مطابق طرح دارد؛ این مقدار
  ادعای مجازبودن چهار حلقه در فروشگاه نیست.
- وابستگی جدید صرفاً SDK تلگرام و tzdata است؛ HTTPX وابستگی Telegram است و
  هیچ مسیر خرید/ورود HTTP خارج از UI فروشگاه اضافه نشده است.
- GitHub، انتشار، تنظیم Pages، CI راه‌دور یا خرید زنده جزو این اجرا نیستند.

نتیجهٔ نهایی تست این پیاده‌سازی در ادامهٔ
[verification.md](verification.md) ثبت می‌شود. پوشش محلی، تست انسانی محیط واقعی یا
تأیید نبود اطلاعات شخصی در پروفایل Chromium نیست.
